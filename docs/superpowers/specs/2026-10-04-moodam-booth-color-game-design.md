# 무담 부스 게임 설계 — "그 색에 멈춰라"

작성일: 2026-10-04

## 1. 배경과 목적

캠핑 컨벤션(금·토·일 3일, 행사 총 참관객 약 20,000명)에 무담(MOODAM) 부스로 참가한다.
부스의 목적은 세 가지다.

1. **집객** — 통로를 지나가는 사람을 부스 앞에 멈춰 세운다
2. **제품 각인** — 무담 미니 LED 클릭커가 *색이 바뀌는 조명*이라는 사실을 전달한다
3. **리드 수집** — 게임 시작 화면에서 이름·전화번호·개인정보 활용 동의를 받는다

게임은 이 세 가지를 동시에 수행하는 장치다.

### 제약

| 항목 | 값 |
|---|---|
| 실행 기기 | 부스 노트북 또는 태블릿 **1대** |
| 네트워크 | **없다고 가정** (컨벤션 와이파이는 신뢰할 수 없음) |
| 상품 | 무담 미니 LED 클릭커 (12,000원) |
| 상품 수량 | **하루 3개** (1·2·3위), 3일 총 9개 = 108,000원 |
| 부스 방문자 수 | **미정** |

## 2. 핵심 설계 판단

### 2.1 합격선이 아니라 랭킹이다

방문자 수를 예측할 수 없으므로 "몇 점 이상이면 당첨" 방식은 성립하지 않는다.
금요일에 40명만 오면 당첨자가 0명이고, 토요일에 400명이 오면 상품이 터진다.

따라서 **일일 랭킹 TOP 3**로 간다. 몇 명이 참가하든 당첨자는 정확히 3명이다.
상품 소진 리스크가 구조적으로 제거된다.

부수 효과가 더 크다.

- 대기 화면의 **오늘의 TOP 3 보드**가 집객 장치로 작동한다
- 참가자가 자기 등수를 확인하러 부스로 되돌아온다
- 친구를 데려와 "내 기록 깨봐"를 시킨다
- **전화번호를 받는 명분이 생긴다**: "오늘 마감 후 TOP 3에게 문자로 안내드립니다"

마지막 항목이 특히 중요하다. "홍보 목적으로 쓰겠습니다"는 거부당하지만, "당첨 연락을 위해 필요합니다"는 거부당하지 않는다.

### 2.2 점수는 연속값이어야 한다

랭킹이 성립하려면 점수가 소수점까지 갈려야 한다.
"맞힌 개수" 같은 이산 점수는 동점자가 수십 명 나와 TOP 3를 정할 수 없다.

### 2.3 밝기가 아니라 색이다

초기 안은 "목표 밝기에 맞춰 멈추기"였으나 **색상 맞추기**로 변경했다.

무담 미니 LED 클릭커의 제품적 재미는 밝기가 아니라, 누를 때마다 파랑·보라·초록·민트로 바뀌는 **색**이다.
밝기 게임은 이 기능을 전달하지 못한다. 색상 게임은 12초 동안 제품 기능을 그대로 보여준다.

집객 측면에서도 유리하다. 회색 게이지가 왕복하는 화면보다 무지개가 휘몰아치다 멈추는 화면이 멀리서 눈에 띈다. 컨벤션장은 조도가 낮아 효과가 더 커진다.

채점 방식은 동일하게 깔끔하다. 색상환 각도 차이가 연속값이기 때문이다.

## 3. 게임 메커니즘

### 3.1 한 판의 흐름

화면 중앙에 무담 미니 LED 클릭커(제품 사진)가 있다.

1. **목표 색 제시** — 화면 상단에 목표 색이 채워진 클릭커 실루엣으로 표시된다
2. **색 순환** — 중앙 클릭커의 갓등이 색상환을 빠르게 돈다
3. **정지** — 화면 탭 또는 스페이스바
4. **채점** — 멈춘 색과 목표 색의 **색상환 거리**(0~180°)가 오차

이것을 **2라운드** 반복한다. 2라운드는 순환 속도가 더 빠르다.

### 3.2 점수

```
라운드 점수 = 100 × (1 − 오차 / 180)   # 오차 0°면 100점, 180°면 0점
총점 = 라운드1 + 라운드2 + 보너스       # 소수점 첫째 자리까지
완벽 보너스 = 오차가 3° 이내일 때 라운드당 +10
```

- **만점 200점**, 두 라운드 모두 완벽하면 보너스가 붙어 최대 220점
- 오차를 그대로 빼는 방식은 쓰지 않는다. 라운드당 오차가 최대 180°라 2라운드면 총점이 음수가 된다
- 오차를 실수로 유지하므로 동점은 사실상 발생하지 않는다
- 동점 발생 시 **먼저 기록한 사람이 상위**

색상환 거리는 지각적 균등성(녹색 구간이 넓게 느껴지는 현상)을 보정하지 않은 단순 각도차를 쓴다. 참가자에게 설명 가능하고 누구에게나 동일하게 적용되는 쪽이 부스 게임에서는 더 중요하다.

### 3.3 난이도

순환 속도는 **파일 상단 상수로 분리한다.**

```
ROUND_SPEED = [120, 180]   // 도/초
```

금요일 기록 분포를 보고 토·일 난이도를 조정할 수 있어야 한다.
점수가 상단에 몰리면 속도를 올리고, 너무 흩어지면 내린다.
랭킹은 날짜별로 독립 집계되므로 난이도를 바꿔도 공정성 문제가 없다.

### 3.4 소요 시간

| 단계 | 시간 |
|---|---|
| 이름·번호·동의 입력 | ~14초 |
| 2라운드 플레이 | ~8초 |
| 결과 확인 | ~12초 (자동 전환) |
| **1인 총계** | **~34초** |

시간당 약 105명 처리 가능. 기기 1대로 충분하며, 줄이 서는 편이 집객에 유리하다.

## 4. 화면

### 4.1 대기 화면 (ATTRACT)

- 배경: `assets/mood-warm-dark.jpg` (어두운 방의 따뜻한 무담 램프)
- **오늘의 TOP 3** 보드 — 1·2·3위 닉네임과 점수
- 하단에 상품 안내: "오늘의 TOP 3에게 무담 미니 LED 클릭커를 드립니다"
- 중앙의 클릭커가 천천히 색을 바꾸며 호흡한다 (무인 상태에서의 시선 유도)
- "화면을 탭하세요"

### 4.2 입력 화면

구글폼을 대체하는 화면이다. 이 한 화면에서 리드 수집이 끝난다.

- 이름
- 휴대폰 번호 (입력하는 대로 `010-0000-0000` 형태로 자동 정리)
- 개인정보 수집·이용 동의 체크 (필수)

폼을 따로 돌리지 않는 이유는 당첨자 대조 때문이다. 폼과 게임 기록이 나뉘어 있으면 마감 후에 두 데이터를 사람 손으로 맞춰야 한다. 한 화면에서 받으면 당첨자가 자동으로 특정된다. 와이파이가 없어도 동작한다는 이점도 있다.

### 4.3 플레이 화면

- 상단: 목표 색 / 라운드 표시 (1 of 2)
- 중앙: 색이 순환하는 무담 클릭커
- 정지 시 멈춘 색으로 고정되고, 오차에 따라 빛 번짐의 세기가 달라진다
- 오차 3° 이내면 "딱!" 연출 — 화면 전체가 그 색으로 한 번 번진다

### 4.4 결과 화면

- 최종 점수
- **현재 등수** ("지금 2위!")
- TOP 3 안이면: "마감까지 유지하면 당첨입니다"
- TOP 3 밖이면: **"3위까지 7.3점"** ← 재도전과 친구 소환을 유발하는 핵심 문구
- 8초 후 자동으로 대기 화면 복귀

## 5. 참가·당첨 규칙

### 5.1 참가

- **1인 1판**, 한 판은 2라운드다
- 중복 식별은 **전화번호**로 한다. 같은 번호로 그날 두 번째 시도를 하면 막힌다
- 운영자 패널에서 제한을 풀 수 있다 (오입력 구제용)

### 5.2 당첨

- 마감 후 당일 TOP 3 확정
- 당첨자에게 문자 발송
- 금·토 당첨자는 다음 날 부스에서 수령 가능
- 일요일 당첨자는 문자로 배송 정보를 회신받아 발송한다 → 입력 화면에서 주소를 받지 않는다 (입력이 짧을수록 참여율이 높다)

### 5.3 개인정보

게임 앱이 이름과 전화번호 전체를 기기에 저장한다. 따라서 다음을 지킨다.

- 입력 화면에 **수집 항목·목적·보유 기간을 명시한 필수 동의**를 둔다. 동의 여부와 동의 문구 버전이 기록에 함께 저장된다
- 동의 문구는 법무 검토 후 확정한다. 현재 문구는 일반적인 경품 행사 기준으로 작성한 초안이다
- 행사가 끝나고 CSV를 안전한 곳으로 옮긴 뒤 **운영자 패널에서 전체 기록을 삭제한다**
- 기기에 화면 잠금을 걸어 둔다

## 6. 기술 구조

### 6.1 형태

**단일 HTML 파일.** 인터넷 없이 열어서 바로 돌아간다. 빌드 과정 없음.

| 항목 | 방식 |
|---|---|
| 저장소 | `localStorage` |
| 입력 | 터치 + 스페이스바 |
| 화면 | 태블릿 세로 / 노트북 가로 모두 대응 |
| 화면 꺼짐 | Wake Lock API + 기기 자동잠금 해제 |
| 이미지 | 리사이즈 후 Base64 인라인 (원본 14~26MB → 각 300KB 이하) |

### 6.2 데이터 모델

```js
localStorage["moodam.plays.v1"] = [
  { date: "2026-10-10", nick: "지훈", tail: "4821", score: 183.4, ts: 1760000000000 }
]
```

랭킹은 `date`로 필터 → `score` 내림차순 → 상위 3개. 동점은 `ts` 오름차순.

### 6.3 운영자 패널

화면 **좌측 상단 모서리를 5회 연타**하면 열린다.

- 오늘 전체 기록 **CSV 내보내기**
- 특정 기록 삭제 (오입력·장난 제거)
- 중복 참가 제한 해제
- 난이도 상수 조정
- 날짜 수동 지정 (테스트 및 자정 넘김 대응)

## 7. 실패 모드와 대응

| 위험 | 대응 |
|---|---|
| localStorage 유실 | **매일 마감 시 CSV 내보내기 필수.** 이걸 안 하면 당첨자가 사라진다 |
| 기기 화면 꺼짐 | Wake Lock + 기기 설정에서 자동잠금 해제 |
| 배터리 방전 | 충전기 상시 연결 (3일 × 8시간) |
| 한 사람이 반복 참가 | 닉네임+뒷4자리 기준 1일 2회 제한, 운영자 해제 가능 |
| 장난 기록이 1위 점유 | 운영자 패널에서 개별 삭제 |
| 점수가 상단에 몰림 | 다음 날 `ROUND_SPEED` 상향 |
| TOP 3가 전부 폼 미제출 | 승계 규칙으로 처리 (안내판 명시) |
| 구글폼 작성 병목 | 폼은 **QR 안내판**으로 분리해 방문자 본인 휴대폰에서 작성. 게임 기기는 게임 전용 |

## 8. 에셋

`assets/` 에 정리되어 있다.

| 파일 | 용도 |
|---|---|
| `lineup-3colors.jpg` | 흰 배경 3색 제품컷 — 누끼 따서 **게임 캐릭터**로 사용 |
| `glow-teal-closeup.jpg` | 발광 연출의 색감·번짐 기준 |
| `glow-blue-hand.jpg`, `glow-green-hand.jpg` | 색상 레퍼런스 |
| `family-blue.jpg`, `family-purple.jpg` | 결과 화면 배경, 상품 안내 (대형 램프 판매에도 기여) |
| `mood-warm-dark.jpg` | 대기 화면 배경 |
| `prize-handful.jpg` | "오늘 3개 한정" 안내 |

전부 원본이 14~26MB다. 게임에 넣기 전 리사이즈가 필요하다.

## 9. 범위 밖

다음은 이번 구현에 포함하지 않는다.

- 서버, 계정, 온라인 랭킹
- 멀티플레이 / 동시 대전
- 사운드 (부스 소음에 묻히고, 음소거 상태로 운영될 가능성이 높다)
- 3일 통합 랭킹 (일일 랭킹만 운영한다)
- 결제·주문 연동
